# Bugbot Re-review Report

- 审查时间：2026-08-23 13:06:47（Asia/Shanghai）
- 审查范围：当前分支相对默认基线的全部变更
- 审查重点：最新修复后的 C-01、P1、P2 后端实现
- 审查结论：发现 8 项问题，其中 P1 5 项、P2 3 项；C-01、P1、P2 仍不能判定全部完成。

## Findings

### P1 — 数据库浏览接口缺少租户身份上下文

- 位置：`backend/api/db_operations.py:617`
- 数据库状态、重连、表列表、表结构及表数据接口未调用 `get_current_user`。
- JWT 用户不会建立租户上下文并落入 `default` 租户；旧全局 API Key 也可绕过多租户模式限制。

### P1 — Agent 文档工具缺少租户过滤

- 位置：`backend/agent/tools/__init__.py:195`
- `list_documents` 和 `get_document_info` 未按 `tenant_id` 过滤。
- 用户可通过聊天工具读取其他租户的文档元数据。

### P1 — 提前断开流可绕过配额计费

- 位置：`backend/api/chat.py:179`
- 流式请求在最终 usage 事件前断开时记录 0 token，并释放完整预留额度。
- 用户可反复提前断流，实际消耗模型资源但绕过配额和计费。

### P1 — 账单幂等与查询没有完整租户作用域

- 位置：`backend/api/billing.py:51`
- 发票二次去重查询缺少 `tenant_id`。
- 付款幂等键和付款查询也采用全局作用域，可能产生跨租户账单泄露或幂等键冲突。

### P1 — 租户管理员错误修改全局用户属性

- 位置：`backend/api/auth.py:165`
- 租户管理员修改成员角色时更新全局 `User.role`，而不是当前租户的 `Membership.role`。
- 停用用户和修改密码也会影响该用户在其他租户中的账户。

### P2 — 通知偏好和列表未完整限定租户

- 位置：`backend/notifications.py:51`
- 用户通知偏好、通知列表和未读计数没有完整限定当前租户。
- 一个租户的偏好可能错误影响同一用户在其他租户中的通知。

### P2 — 审批状态操作没有校验被指派人

- 位置：`backend/api/db_operations.py:1018`
- `expire`、`escalate` 和 `transfer` 未校验当前用户是否为任务的 `assigned_to`。
- `escalate` 允许写入不存在或属于其他租户的 assignee。

### P2 — 恢复任务接口跨租户泄露

- 位置：`backend/api/db_operations.py:1534`
- `/audit/recovery-pending` 没有按 `tenant_id` 过滤。
- 租户管理员可看到其他租户的恢复任务信息。
