# Security Review 报告

审查范围：当前工作区未提交改动（身份认证、RBAC、敏感数据脱敏、SQL 标识符处理、备份回滚事务化、双人审批、审核队列、设置接口、中间件）。

结论：发现 1 个高优先级授权缺陷、3 个中优先级风险、4 个低优先级加固项。

## 高优先级

### 1. 设置接口未限制角色，低权限用户可篡改模型凭据

- 严重度：High
- 位置：`backend/api/settings.py` `update_settings`
- 问题：`PUT /api/settings` 只受全局 Bearer 认证保护，没有 `require_roles("admin")`；任何已登录用户（包括 `viewer`）都能修改 `LLM_*` / `EMBEDDING_*` 凭据和功能开关。
- 风险：攻击者可把 `llm_base_url` 改为自己控制的 OpenAI 兼容服务，从而在后续所有对话中截获用户提示词、知识库内容和数据库查询结果。
- 建议：`update_settings` 增加 `require_roles("admin")`；凭据修改单独走更高权限并记录审计。

## 中优先级

### 2. SQL 仍以原始字符串执行，签名式防护可被绕过

- 严重度：Medium
- 位置：`backend/api/db_operations.py` `preview_operation` / `approve_review`、`backend/agent/tools/database.py`
- 问题：SELECT 预览和批准后的写操作都是把 SQL 字符串交给连接器执行，安全依赖关键字正则、多语句检测和 WHERE 黑名单；缺少参数化或更严格的 AST / 语法白名单。
- 风险：虽然写操作有人工审批，但提示注入诱导生成的恶意 SQL 若绕过正则，可能在审批人误批后执行越权操作。
- 建议：长期改为“LLM 输出参数化 SQL + 参数列表”；短期引入更强的 SQL 解析白名单，并对写操作保留人工审核兜底。

### 3. `APP_ENV` 默认 development，误部署会整体关闭认证

- 严重度：Medium
- 位置：`backend/config.py`、`backend/auth.py` `auth_enabled` / `get_current_user`
- 问题：`app_env` 默认值为 `development`，开发模式在未配置持久密钥时把 `api_key` 置空，`auth_enabled` 返回 False，所有请求以 `dev` 管理员身份放行。
- 风险：若生产部署忘记设置 `APP_ENV=production`，服务将完全未鉴权且拥有管理员权限。
- 建议：默认值改为更安全的 `production`，或增加部署检查 / 启动时显式提示；生产环境强制 `APP_ENV=production`。

### 4. 连接测试接口可被用于 SSRF / 内部探测

- 严重度：Medium
- 位置：`backend/api/settings.py` `test_connection`
- 问题：`POST /api/settings/test-connection` 接受任意 `base_url`，并向其发起带自定义 `Authorization` 头的 GET 请求；仅做全局认证，无角色限制。
- 风险：已登录低权限用户可用该接口探测内网地址、端口和 HTTP 服务。
- 建议：限制为管理员角色，并对目标 URL 做协议 / 主机白名单校验，禁止访问内网地址。

## 低优先级

### 5. 审计日志对所有已登录角色开放

- 严重度：Low
- 位置：`backend/api/db_operations.py` `get_operation_logs`
- 问题：`get_operation_logs` 使用 `get_current_user`，`viewer` 也能读取完整 SQL、提交人和审批人信息。
- 建议：改为 `require_roles("approver")` 或按角色过滤敏感字段。

### 6. JWT 存储与实现可加固

- 严重度：Low
- 位置：`backend/auth.py`、`frontend/src/stores/authStore.ts`、`frontend/src/api/client.ts`
- 问题：JWT 存于 `localStorage`，前端无 CSP；手写 JWT 缺少 `alg` / `aud` / `iss`，异常 `exp` 类型可能抛出未处理 ValueError。
- 建议：优先 HttpOnly Cookie；为前端配置 CSP；JWT 增加标准声明并对 `exp` 做防御性解析。

### 7. 登录缺少账号锁定，限流为进程内实现

- 严重度：Low
- 位置：`backend/api/auth.py` `login`、`backend/middleware/ratelimit.py`
- 问题：登录仅依赖按 IP 的进程内滑动窗口限流，无账号级失败锁定；多 worker 部署时各自计数，限流效果下降。
- 建议：增加账号级失败锁定，生产环境将限流状态迁移到 Redis。

### 8. 开发模式备份快照密钥随会话变化

- 严重度：Low
- 位置：`backend/db_connector/backup.py`、`backend/config.py`
- 问题：开发模式未设置持久 `SECRET_KEY` 时，备份快照用会话级随机密钥加密；重启后旧快照无法解密，回滚会失败。
- 建议：开发模式对备份使用稳定本地密钥，或明确禁止跨重启回滚并给出提示。
