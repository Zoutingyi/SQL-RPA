# 用户体系后端技术栈清单

来源：`用户整改.md`  
生成日期：2026-08-25  
对应计划：[用户整改-后端整改计划.md](用户整改-后端整改计划.md)

文档状态：**V1.0 商业交付技术基线**  
适用范围：`backend/` 用户、认证、组织任职、个人资料、改密、迁移和运维能力。

## 零、技术基线说明

- “现有”表示已在当前 `requirements.txt` 或代码中使用，不等于用户整改功能已经完成。
- “本期必须”表示商业交付前必须实现、锁版并通过测试；不得以设计文档或 mock 代替。
- `requirements.txt` 当前使用宽松下限，不能直接作为可复现生产依赖。发布时必须生成带哈希的
  锁定依赖文件，记录 Python、操作系统、CPU 架构、许可证和漏洞扫描结果。
- 当前代码使用 PBKDF2-HMAC-SHA256 和自实现 HMAC 令牌。本期保持兼容，但认证实现必须通过
  Security Review；Argon2id 和标准 JWT/OIDC 迁移作为单独版本演进，不与本次整改混做。

## 一、语言与运行时

- Python `>=3.12,<3.15`：后端运行时。
- Uvicorn `>=0.30`：ASGI 服务和多 worker 部署。
- asyncio：异步数据库、缓存和审计事件处理。
- 本期生产基线固定为 Python 3.12.x；3.13/3.14 仅在完整依赖与回归测试通过后进入支持矩阵。
- 容器镜像必须固定 digest，使用非 root 用户运行，设置只读根文件系统和独立可写数据目录。

## 二、Web 与接口契约

- FastAPI `>=0.115`：登录、用户管理、个人资料和改密 API。
- Pydantic `>=2.10`：请求/响应 Schema、字段格式和 `extra='forbid'`。
- pydantic-settings `>=2.7`：默认管理员、密码策略和生产配置。
- OpenAPI：前后端接口、错误码、只读字段和强制改密状态契约。
- httpx `>=0.25`：ASGI 接口测试和集成验证。

商业交付约束：

- Pydantic 请求模型统一 `extra='forbid'`；响应使用显式 `response_model`，禁止直接序列化 ORM。
- OpenAPI 是字段和状态码唯一事实来源；提交必须包含 OpenAPI 快照差异和契约测试。
- 所有错误使用 `{error: {code, message, field_errors, request_id}}`，业务客户端不得解析自由文本。
- 时间统一 ISO 8601 UTC，ID 统一字符串 UUID，分页默认 20、最大 100。

## 三、数据库与事务

- SQLAlchemy Async `>=2.0.36`：User、OrganizationMembership、审计和幂等记录 ORM。
- AsyncSession：用户与主职 Membership 原子创建。
- Alembic `>=1.14`：用户字段、唯一索引和历史数据 upgrade/downgrade。
- PostgreSQL 17 + asyncpg `>=0.30`：生产数据库、部分唯一索引、行锁和并发验收。
- SQLite + aiosqlite `>=0.20`：本地开发和快速单元测试，不作为生产并发结论。

生产支持矩阵：PostgreSQL 17.x、Redis 7.2.x；版本固定到补丁版本和镜像 digest。SQLite 仅供
单元测试和本地演示，任何唯一约束、并发、迁移、行锁和事务结论必须在 PostgreSQL 验证。

关键数据库能力：

- `lower(username)` 唯一函数索引或规范化用户名唯一列。
- User 与 OrganizationMembership 同事务提交。
- 创建接口幂等键数据库唯一约束。
- `SELECT ... FOR UPDATE` 或条件 UPDATE 处理并发状态变化。
- token version、强制改密状态和密码更新时间持久化。
- 平台管理员初始化使用数据库唯一约束，保证多个服务实例并发启动时只产生一个默认管理员。
- 用户创建幂等记录保存操作者、键、请求摘要、结果资源和到期时间；同键不同摘要固定返回 409。
- 用户和任职更新使用整数 `version` 乐观锁，零行更新返回稳定 409，禁止最后写入静默覆盖。

## 四、认证与密码安全

- 项目现有 HMAC-SHA256 JWT 风格令牌：继续使用并增加 `token_version`。
- `hashlib.pbkdf2_hmac`：兼容现有密码哈希。
- `hmac.compare_digest`：密码派生结果和令牌签名恒定时间比较。
- `secrets`：盐、令牌 ID 和幂等标识生成。
- 建议后续密码哈希升级：Argon2id；迁移采用登录时渐进重哈希，不能破坏旧哈希。

本期密码与令牌硬指标：

- 默认 `admin/admin` 与用户默认 `111111` 只以哈希存储，首次登录必须改密。
- PBKDF2 参数、盐长度和算法标识写入哈希字符串；参数升级通过登录时渐进重哈希完成。
- 访问令牌必须包含唯一 `jti` 和 `token_version`；验签后每次请求还要校验账号启用状态及
  token version，不能只相信令牌中的角色。
- 平台访问令牌不得携带可访问全部组织的隐式权限；组织上下文令牌必须绑定
  company、organization、membership 和 context version，最长有效期 15 分钟。
- 密钥来自生产密钥管理或受控 Secret，不允许使用代码默认值；支持密钥版本和轮换窗口。

令牌至少包含：

- `sub`
- `jti`
- `iat`、`exp`
- `token_version`
- `platform_admin`
- 组织上下文令牌另含 company、organization、membership、role 和 context version。

## 五、会话失效与缓存

- Redis Server 7.x。
- redis-py asyncio `>=5.0`。
- 用于 token version 快速读取、JTI 撤销、强制改密门禁缓存和多 worker 失效广播。
- Redis 不可用时必须安全失败或回查数据库，不能默认放行旧令牌。
- 改密、停用用户和停用 Membership 后发布失效事件。
- 撤销事件必须包含用户 ID、最新 token version、原因和时间，不包含用户名、电话或令牌。
- 缓存键必须带部署环境和业务命名空间；TTL 不得长于其对应令牌或授权上下文有效期。

## 六、权限与组织上下文

- FastAPI Dependency：统一认证、平台权限和 OrganizationMembership 权限校验。
- ContextVar：保存当前不可变用户及组织上下文快照。
- `resolve_organization_context()`：验证账号、组织、Membership、有效期和角色。
- `require_platform_admin()`：平台接口权限。
- `require_user_management()`：用户管理权限，不复用普通部门 admin 字符串判断。
- `require_password_changed()`：强制改密门禁。
- `require_resource_scope()`：阻止平台管理员无部门上下文访问业务资源。

授权链固定顺序：认证令牌 → User 启用状态/token version → 强制改密门禁 → 平台或组织上下文
类型 → Membership 有效性/context version → 功能角色 → 资源作用域。任一环节失败即拒绝，
禁止用旧 `User.role`、请求头或前端传值补全缺失权限。

## 七、输入校验与隐私

- Pydantic `field_validator`：用户名、姓名、职位、电话和密码确认校验。
- 正则表达式：用户名字符白名单和可配置电话号码格式。
- 项目统一 masking 工具：电话和敏感字段脱敏。
- 结构化日志字段过滤器：屏蔽 password、password_hash、current_password、new_password 和 confirm_password。
- FastAPI 请求模型禁止额外字段，防止 Mass Assignment。
- 电话以加密或等效受控字段保存；检索如有需要另存不可逆规范化摘要。默认 API 只返回脱敏值，
  完整值必须由独立权限、用途说明和审计保护。
- 用户名、姓名、职位和电话定义统一长度上限，拒绝控制字符和双向文本控制符，避免日志与 UI
  欺骗；姓名不得被自动改写为用户名。

## 八、速率限制与幂等

- Redis 原子计数或 Lua：登录、改密和创建用户限速。
- 数据库幂等表或用户创建审计表：保存 Organization、操作者、Idempotency-Key 和请求摘要。
- 用户名唯一索引作为最终并发同步点。
- 唯一冲突时回读既有结果或返回稳定 409，不返回 500。
- 限速维度至少包含操作类型、来源 IP、操作者或目标账号；多 worker 必须共享 Redis 状态。
- Redis 限速不可用时，登录和改密采用保守限速或安全失败；创建用户不得退化为无限制操作。

## 九、安全审计

- 现有 DomainEvent/Outbox：用户创建、资料变化、启停、任职和密码事件。
- 现有审计哈希链：保存防篡改操作记录。
- 审计字段包含 actor、target user、company、organization、membership、IP、request ID、结果和时间。
- 审计中禁止保存密码、密码哈希、完整电话和认证头。
- 平台管理员无组织操作使用独立事件类型。
- 审计写入采用与业务事务一致的 Outbox；审计落库失败时用户创建、启停、权限和改密操作不得
  无记录成功。
- 审计数据定义保留期、归档、查询权限和完整性校验任务；平台管理员查询也必须被审计。

## 十、错误契约

- 复用稳定错误响应模块 `api_errors.py`。
- V1 固定错误码至少包含：

  - `INVALID_CREDENTIALS`
  - `ACCOUNT_LOCKED`
  - `USERNAME_ALREADY_EXISTS`
  - `IDEMPOTENCY_KEY_REQUIRED`
  - `IDEMPOTENCY_CONFLICT`
  - `USER_MANAGEMENT_FORBIDDEN`
  - `USER_NOT_FOUND`
  - `USER_VERSION_CONFLICT`
  - `ORGANIZATION_OUT_OF_SCOPE`
  - `MEMBERSHIP_CREATE_FAILED`
  - `PASSWORD_CHANGE_REQUIRED`
  - `CURRENT_PASSWORD_INVALID`
  - `PASSWORD_CONFIRMATION_MISMATCH`
  - `PASSWORD_POLICY_FAILED`
  - `TOKEN_REVOKED`
  - `PLATFORM_CONTEXT_REQUIRED`
  - `ORGANIZATION_CONTEXT_REQUIRED`

- 权限错误不暴露目标用户、组织或 Membership 是否存在。

## 十一、迁移工具

- Alembic：结构升级与降级。
- SQLAlchemy Core：分批数据迁移和校验。
- SQLite Online Backup API：本地内部数据库迁移前备份。
- PostgreSQL 事务：生产迁移批次和 checkpoint。
- JSON/结构化日志：dry-run、批次进度、错误和对账报告。

迁移交付物必须包含：预检查 SQL、数据备份、dry-run 报告、upgrade、逐项对账、异常隔离清单、
downgrade、预计锁表时间和回滚决策点。生产迁移不得在应用启动请求路径中自动执行。

## 十二、测试与质量工具

- pytest：单元、服务和迁移测试。
- pytest-asyncio：异步事务、认证和并发测试。
- pytest-cov：用户模块 statement coverage `>=90%`、branch coverage `>=85%`。
- httpx ASGITransport：FastAPI 权限及错误契约测试。
- Ruff：静态检查和导入质量。
- `python -m compileall`：语法门禁。
- GitHub Actions：单元、PostgreSQL、Redis、多 worker、迁移和安全测试。
- pip-tools 或等效锁定工具：从声明依赖生成带哈希的生产锁文件；不得使用未锁定的在线安装结果交付。
- CycloneDX 或等效工具：生成 Python SBOM；结合依赖漏洞和许可证扫描作为发布门禁。
- Bandit/Semgrep 或等效 SAST：检查认证、密码、日志、SQL 和危险默认配置；命中高危时阻止交付。

## 十三、真实集成环境

- PostgreSQL 17：用户名唯一、事务回滚和并发创建。
- Redis 7.x：改密、停用和多 worker 令牌撤销。
- 4 个 Uvicorn worker：旧会话失效及限速一致性。
- 固定版本容器，禁止使用 `latest`。
- 参考压测环境固定为 4 vCPU、8 GiB 内存、PostgreSQL 和 Redis 独立实例、4 个 Uvicorn worker；
  报告必须记录数据量、并发、持续时间、p50/p95/p99、吞吐和错误率。

## 十四、建议性能与一致性指标

- 50 并发基线下，登录和 `/api/auth/me` p95 `<=250 ms`。
- 50 并发基线下，用户列表 p95 `<=500 ms`，用户创建和改密 p95 `<=800 ms`，不包含外部通知。
- 改密后旧令牌跨 worker 失效 p99 `<=5 秒`。
- 100 个并发重复用户名创建时成功记录数恒为 1，500 数为 0。
- 用户与 Membership 事务一致率 100%。
- 权限为空账号业务接口越权成功数为 0。
- 密码及密码哈希日志泄露数为 0。
- 用户模块 statement coverage `>=90%`、branch coverage `>=85%`。
- 压测期间 5xx 比例 `<0.1%`，跨组织、空权限和强制改密绕过成功数恒为 0。
- 审计事件与成功敏感操作对账差异为 0。

## 十五、依赖使用限制

- 不新增第二套 ORM、认证框架或 Redis 客户端。
- 不将密码改为可逆加密保存。
- 不在内存中维护生产级 token 撤销状态。
- 不使用前端隐藏按钮代替后端权限校验。
- 不使用全局 `User.role` 表示部门权限。
- 新依赖必须记录版本、用途、许可证和安全扫描结果。

## 十六、配置与可观测性

- 环境变量按开发、测试、预生产和生产分层；启动时校验关键配置，生产缺少密钥、数据库、Redis
  或管理员初始化策略时直接失败，不带危险默认值运行。
- 健康检查分为 liveness 和 readiness；readiness 必须反映数据库、迁移版本和关键授权依赖状态。
- 指标只使用低基数标签：接口、状态码、错误码和结果；禁止用户名、电话、用户 ID、组织名和
  request ID 作为指标标签。
- 结构化日志贯穿 `request_id`，安全审计可由 request ID 关联，但日志中不得保存请求正文、
  Authorization、Cookie 或密码字段。

## 十七、商业交付技术门禁

- [ ] Python、数据库、Redis、容器和所有依赖版本已锁定并可离线复现。
- [ ] OpenAPI、数据库模型、迁移、前端契约和错误码完全一致。
- [ ] 默认管理员、多实例初始化、默认密码强制改密和无组织隔离通过真实环境测试。
- [ ] 改密、停用和任职失效后，旧令牌在全部 worker 中按指标失效。
- [ ] PostgreSQL 并发、Redis 故障、审计失败和迁移回滚演练通过。
- [ ] 覆盖率、SAST、依赖漏洞、许可证、SBOM、Bugbot 和 Security Review 门禁通过。
- [ ] 运维手册、数据字典、OpenAPI、迁移手册、回滚手册和测试报告已归档。
