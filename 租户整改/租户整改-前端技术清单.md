## 技术栈与版本基线

以下版本以当前 `frontend/package.json` 为准；升级版本必须单独评估，不得在本整改中隐式替换框架。

- **运行与构建**：Node.js `>=20.19`（CI 固定 Node.js 22）、npm、Vite `8.1.x`、TypeScript `6.0.x`。
- **UI 框架**：React `19.2.x`、React DOM `19.2.x`、React Router DOM `7.18.x`。
- **状态管理**：Zustand `5.0.x`；组织上下文为唯一全局身份状态源，各业务 Store 通过统一 reset registry 清理。
- **样式**：Tailwind CSS `4.3.x`、现有 `index.css` 设计变量；组织树使用 React 递归组件与 WAI-ARIA Tree 模式，不额外引入整套 UI 框架。
- **网络与流式处理**：浏览器原生 `fetch`、`AbortController`、`ReadableStream`、SSE；所有请求由统一 API Client 注入上下文。
- **本地持久化**：浏览器 `localStorage` 仅保存后端签发的上下文标识/令牌；不得保存权限集合、敏感业务数据或作为授权依据。
- **单元/组件测试**：Vitest `4.1.x`、React Testing Library `16.3.x`、user-event `14.6.x`、jsdom `30.x`、jest-dom `7.x`。
- **端到端测试（本整改新增）**：Playwright Test，与 Chromium 无头模式配合；版本与落地时最新兼容 Node 22 的稳定版锁定。
- **覆盖率与无障碍（本整改新增）**：`@vitest/coverage-v8`、`@axe-core/playwright`，版本与 Vitest/Playwright 主版本对齐。
- **质量门禁**：Oxlint `1.69.x`、`tsc -b`、Vite production build、GitHub Actions。

### 需要新增并锁定的开发依赖

- `@playwright/test`：组织切换、权限隔离和窄屏E2E；加入`devDependencies`并固定版本。
- `@vitest/coverage-v8`：statement/branch覆盖率；版本与Vitest 4主版本一致。
- `@axe-core/playwright`：部门树和切换弹窗无障碍扫描；仅作为开发依赖。
- 新增脚本：`test:coverage`、`test:e2e`、`test:e2e:a11y`；CI使用`npm ci`，禁止未锁版本安装。

## 可量化技术指标

指标测试基线：CI 使用 2 vCPU/4 GB 内存、Node.js 22、Chromium headless、production build；前端性能用固定 50 ms mock API 延迟测量，后端真实耗时另行统计。所有百分位至少采集 100 次，预热 10 次不计入结果。

- **FE-M01 上下文覆盖率**：普通 API、FormData、聊天流和 SSE 的组织请求头覆盖率必须为 `100%`；业务目录裸 `fetch` 静态扫描违规数为 `0`。
- **FE-M02 身份原子性**：连续切换主职/兼职 100 次，旧身份响应写入新 Store 的次数为 `0`，混合展示旧组织数据的次数为 `0`。
- **FE-M03 切换反馈时延**：点击确认后 `100 ms` 内进入锁定/加载状态；切换接口成功后上下文提交与旧缓存同步清理 p95 `<=100 ms`。
- **FE-M04 请求终止**：上下文提交后，旧聊天 SSE、审核轮询、上传和可取消 HTTP 请求 p95 在 `250 ms` 内收到 abort；遗留活动请求数为 `0`。
- **FE-M05 树性能**：2,000 个可见组织节点数据下，首屏可交互 p95 `<=1,000 ms`，单节点展开/折叠与搜索输入响应 p95 `<=100 ms`；超过 2,000 节点必须采用懒加载或虚拟化。
- **FE-M06 文案一致性**：普通用户可见 DOM、Toast、错误、空状态、ARIA label 和快照中的“租户”命中数为 `0`；兼容代码与开发日志必须在白名单中。
- **FE-M07 权限来源**：业务按钮/路由使用全局 `user.role` 直接授权的新增调用数为 `0`；组织业务权限 `100%` 来源于当前 Membership 上下文。
- **FE-M08 状态隔离**：会话、文档、记忆、数据库、审核、通知、用量、账单、设置/成员共 9 类作用域状态必须 `100%` 注册清理器并有自动化断言。
- **FE-M09 无障碍**：部门树与切换弹窗满足 WCAG 2.1 AA；键盘路径覆盖率 `100%`，axe critical/serious 缺陷数为 `0`。
- **FE-M10 测试覆盖率**：新增组织模块 statement coverage `>=90%`、branch coverage `>=85%`；四级节点 × 主/兼职 × 401/403/409 的规定用例通过率 `100%`。
- **FE-M11 稳定性**：E2E 身份切换矩阵连续执行 20 轮，未处理 Promise rejection、React error 和 console error 数均为 `0`。
- **FE-M12 体积预算**：部门管理与身份切换新增代码对主入口 gzip 增量 `<=60 KB`；超过预算必须拆分路由 chunk 或说明原因。
- **FE-M13 安全存储**：LocalStorage/SessionStorage 中权限、用户业务数据和数据库配置明文条目数为 `0`；修改本地上下文后越权成功数为 `0`。
- **FE-M14 CI 门禁**：lint、类型检查、单元测试、覆盖率、E2E、文案扫描、裸请求扫描和生产构建必须全部通过，允许失败项数为 `0`。
