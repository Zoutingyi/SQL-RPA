### [x] TB-BUG-01 组织上下文与兼容租户头未绑定（后端已完成）

> 后端完成记录（2026-08-25）：兼容租户 ID 统一由已验证组织上下文派生；不一致请求返回 403 并写入安全事件，负向回归测试已通过。

- 责任端：后端
- 位置：`backend/auth.py:221`
- 问题：组织上下文校验成功后，`tenant_id` 仍可优先取客户端提交的 `X-Tenant-ID`，但没有验证其与已认证的 `organization_id` 一致。
- 风险：攻击者可能携带组织 A 的有效任职，同时提交组织 B 的租户头，以组织 A 的角色访问组织 B 的文档、数据库、审批或账单，构成跨组织授权绕过。
- 整改要求：
  1. 在组织模式下，服务端必须从已验证的组织/任职上下文派生兼容 `tenant_id`，不得信任客户端独立指定的租户值。
  2. 如兼容期仍接收 `X-Tenant-ID`，必须强制其与当前组织映射一致；不一致统一返回 `403` 并写入安全审计日志。
  3. 所有依赖租户兼容字段的鉴权入口使用同一校验函数，禁止各接口自行回退。
- 完成标准：构造“组织 A 任职 + 组织 B 租户头”的请求，所有受保护资源均返回 `403`，且不存在跨组织数据读取或写入。

### [x] TB-BUG-04 审批幂等键未按组织隔离（后端已完成）

> 后端完成记录（2026-08-25）：审批幂等边界、唯一约束和冲突重查均加入 `organization_id`，存储键兼容旧全局索引且不返回跨组织任务。

- 责任端：后端
- 位置：`backend/api/db_operations.py:886`
- 问题：审批提交只按全局 `idempotency_key` 查询，数据库字段也采用全局唯一约束，没有组织条件。
- 风险：组织 B 复用组织 A 的幂等键时可能直接获得组织 A 的审批任务，泄露 SQL 和审核信息；并发冲突路径同样存在问题。
- 整改要求：
  1. 幂等查询至少按 `organization_id + idempotency_key` 组合限定；如业务要求更细，应加入 `membership_id` 或操作类型。
  2. 数据库唯一约束改为与组织作用域一致的组合唯一约束。
  3. 并发插入冲突后的重查必须使用相同组织条件，并验证资源归属。
- 完成标准：不同组织可安全复用相同幂等键；任何组织均不能读取或返回其他组织的审批对象。

  1. 预留、确认、释放和重试全流程使用 `organization_id + request_id` 作为幂等边界。
  2. 返回已有预留前必须校验组织、用户、资源类型和计费维度全部一致。
  3. 数据库组合唯一约束与业务查询条件保持一致。
- 完成标准：跨组织复用请求 ID 不会互相命中、占用或结算；并发测试中各组织配额独立且账目守恒。

## 二、重要整改项（P2）

### [x] TB-BUG-08 数据库连接缓存隔离维度不足（后端已完成）

> 后端完成记录（2026-08-25）：连接缓存键升级为“组织 + 任职 + 配置版本”；配置更新递增版本并淘汰旧连接，不同任职及版本不共享连接的自动化测试已通过。

- 责任端：后端
- 位置：`backend/db_connector/factory.py:61`
- 问题：连接器缓存仅以租户/组织 ID 为键，不包含 `membership_id` 和配置版本。
- 风险：同一组织内不同任职可能共享连接池；连接配置或密钥更新后，系统可能继续复用旧连接。
- 整改要求：缓存键至少包含组织、任职及配置版本；配置变更、任职失效或组织切换时主动淘汰相关连接，并设置安全的过期策略。
- 完成标准：不同任职不共享应隔离的连接；配置或凭据轮换后旧连接不可继续使用；并发切换测试无串用。

### [x] TB-BUG-09 组织切换时旧请求可能回灌状态（前端已完成）

> 前端完成记录（2026-08-25）：请求保持注册直至响应体和业务 JSON 解析完成；每次请求绑定组织/任职/上下文令牌快照与代次，切换时先失效代次并中止旧 HTTP/SSE。Playwright Chromium 将不可取消的旧组织慢 HTTP 响应体、旧 SSE 分块分别延迟到切换完成后再交付，DOM 回灌均为 0；100 次连续主/兼职切换触发 402 个文档请求，旧组织 DOM 回灌仍为 0。

- 责任端：前端
- 位置：`frontend/src/api/client.ts:54`
- 问题：`trackedFetch` 收到响应头后便从活动控制器集合删除请求，而不是等响应体读取和解析完成。
- 风险：切换组织时无法取消仍在读取响应体的旧请求，旧组织结果可能在状态清理后写回 Zustand，造成陈旧数据或跨组织数据短暂展示。
- 整改要求：
  1. 请求必须在响应体消费及业务解析完成后才从活动集合移除。
  2. 组织切换时中止旧请求、关闭旧 SSE，并使用上下文版本防止无法取消的响应提交状态。
  3. 所有异步 Store 写入前校验请求发起时的组织/任职上下文仍有效。
- 完成标准：在慢响应、流式响应和高频切换场景下，旧组织数据均不能写入或展示到新上下文。
